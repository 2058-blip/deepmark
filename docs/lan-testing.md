# 两台电脑测试协同标注

电脑 A 运行 Deepmark 服务，同时打开网页充当第一个客户端；电脑 B 只使用新版 Edge / Chrome，无需安装 Node.js。两台电脑需要处于能互相访问的同一局域网。请在两台电脑上使用同一个服务器地址，以免切换网址后进入另一份浏览器缓存。

## 1. 在电脑 A 准备 CT

把三维 NIfTI-1 `.nii` 或 `.nii.gz` 文件复制到项目下的 `server-data/datasets/`。允许用子文件夹分类，复制完成后在网页刷新数据集列表即可发现。当前没有网页上传 CT 的入口；本机直接复制进该目录就是放入服务器数据仓库。

也可将 `DATASET_DIR` 指向已有的 CT 文件夹。不要在两位作者测试过程中替换原始文件；内容改变会被识别为另一共享工程。首次测试可使用已有的合成练习影像。

## 2. 在电脑 A 启动服务

本项目需要 Node.js 24+。初次从 GitHub 克隆时先执行 `npm ci`；当前开发电脑已经安装依赖。

在项目文件夹打开 PowerShell：

```powershell
npm run build
$env:HOST = '0.0.0.0'
$env:PORT = '8080'
# 可选：使用自己的影像目录（目录必须已经存在）
# $env:DATASET_DIR = 'D:\CT数据'
npm start
```

8080 提供网页、影像下载、协同 API 和 WebSocket，不需要分别开放多个端口。保持这个 PowerShell 进程运行。服务会把共享结果及历史写入服务器 SQLite 数据库；默认在 `server-data/collaboration/`，重启不会清空。切换 `DATASET_DIR` 时建议同时设置固定的 `STATE_DIR` 保存数据库，避免跟着数据目录切换到另一数据库。

运行 `ipconfig` 查看电脑 A 的 WLAN 或以太网 IPv4 地址，忽略 VMware、VPN 等虚拟网卡。例如地址是 `10.167.128.87`，则两台电脑都打开 `http://10.167.128.87:8080/`。不要在电脑 B 输入 `127.0.0.1` 或 `0.0.0.0`：前者代表电脑 B 自己，后者是服务监听配置。

## 3. 各自加入同一共享工程

两台电脑分别点击“服务器数据集”，选择同一份 CT，点击“下载并标注”，输入不同昵称（例如“工程师 A”和“工程师 B”），点击“加入实时协同”。只从“打开影像”载入本地文件属于本地标注，不会加入共享工程。

- A 在一处绘制，B 应看到对应标注；B 再在另一处绘制，A 应看到更新。
- B 新建第二个标签，在 A 已标注的位置绘制，应出现并列标注条目，保留各作者意见。
- 测试断网：暂时断开电脑 B 的网络，继续画一笔，再恢复网络，待上传操作应重试并同步。
- 测试恢复：使用“同步并退出”，重新打开同一服务器地址、同一数据集并加入协同，应看到服务器最新成果。未完成上传的工作可从原浏览器的“本地工作缓存”恢复。
- 点击“导出标注 ZIP”或“导出审阅 ZIP”，检查包内的分割、标签说明和并列意见。

两个独立浏览器用户配置也可先在同一电脑模拟两位作者；同一浏览器配置下的两个标签页会共享登录 Cookie，不能当成完全独立的作者身份。

## 4. 另一台电脑打不开时

先确认电脑 A 自己能打开该局域网地址，且服务仍在运行。若服务正常，可能需要给 Windows 防火墙增加入站规则。在电脑 A 用管理员权限打开 PowerShell，仅允许本地子网访问 TCP 8080：

```powershell
New-NetFirewallRule -DisplayName 'Deepmark LAN test 8080' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080 -RemoteAddress LocalSubnet
```

不需要关闭防火墙。若仍不通，检查两台电脑是否连接同一网络，以及路由器或校园/办公 Wi-Fi 是否开启了客户端隔离。电脑 A 的 IP 可能在重新联网后改变，请以当时的 `ipconfig` 为准。

此方法用于同一局域网内的协同测试；对外发布时再配置 HTTPS 和正式账号体系。
