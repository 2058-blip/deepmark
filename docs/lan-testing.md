# 两台电脑测试 Java 平台协同标注

服务器运行 Java API、WebSocket 与已构建网页。两台电脑使用新版 Edge / Chrome；浏览器客户端不需要安装 Node.js。请在每台电脑上始终使用选定的同一网址，切换协议、主机名或端口会进入另一份浏览器缓存。

## 1. 准备并启动服务

构建环境需要 JDK 17+、Maven 3.9+ 与 Node.js 24+。在仓库根目录执行：

```sh
npm ci
npm run build
npm run build:server
java -jar backend/target/deepmark-server.jar
```

Java 默认监听 `127.0.0.1:8787`，同时提供网页、影像与协同接口。当前数据库为 `server-data/platform/deepmark.sqlite`，影像目录为 `server-data/datasets`；可以使用 `STATE_DIR` 和 `DATASET_DIR` 指定其他位置。Node.js 负责构建与测试，旧 `server/server.mjs` 仅用于旧协议 fixture，不是本平台启动入口。

Linux 独立部署也可直接使用 [部署脚本](../deploy/README.md)。该方案默认以回环 HTTP 后端配合独立 HTTPS `8443` 入口，原始数据和数据库放在源码目录之外。

## 2. 选择浏览器访问方式

账户密码加密与影像指纹验证使用 Web Crypto。远程浏览器访问使用 HTTPS；普通局域网或公网 IP 的 HTTP 地址不属于支持的登录测试方式。

### 方案 A：局域网或远程 HTTPS

使用同源反向代理，将网页、`/api` 和 WebSocket 一起转发到 Java 后端。两台电脑打开同一个实际 HTTPS 地址，例如 `https://你的服务器主机名:8443/`。证书应包含该主机名，并由两台电脑信任。

独立部署脚本的默认自签证书包含 `ddns.984797.xyz`、`localhost` 和 `127.0.0.1`。测试前明确信任该证书，或安装正常受信任的有效证书；保持 TLS 验证开启。其他局域网 IP 不在此证书 SAN 中，应使用匹配的主机名或为该测试地址配置证书。监听 `8443` 本身不证明公网路由已打通。

### 方案 B：每台电脑通过 SSH 转发到 localhost

若服务器可通过 SSH 到达，每台客户端电脑分别保持以下隧道运行，用户名、主机和 SSH 端口按实际配置填写：

```sh
ssh -N -L 8787:127.0.0.1:8787 -p 2222 your-user@your-server
```

然后两台电脑各自打开 `http://localhost:8787/`。浏览器将 localhost 视为安全上下文，流量经 SSH 到达同一个 Java 服务。保留正常 SSH 主机密钥验证；每台电脑使用自己的账号和浏览器会话，不共享服务端登录身份。

如果本机 `8787` 已占用，可将命令左侧改为 `18787`，并打开 `http://localhost:18787/`。`127.0.0.1` 在这里指本机隧道入口；不要将 `0.0.0.0` 当成浏览器网址。

## 3. 发布一份练习影像

准备三维灰度 NIfTI-1 `.nii` 或 `.nii.gz`。首次测试可以执行 `npm run sample-data`，使用输出的合成练习影像，不必引入患者资料。

注册一个数据发布人员（`dispatcher`，派活）账户，登录派活工作台，选择文件并上传发布。当前任务由网页发布流程建立；把文件复制进 `DATASET_DIR` 不会自动创建任务。测试期间不要直接替换已发布的原始文件，需要变更内容时重新发布。

## 4. 使用两个标注账户协作

电脑 A 和 B 分别注册不同的标注人员（`worker`，干活）账户。若还要同时测试发布人员只读监看，另开一个独立浏览器配置使用派活账户；同一浏览器配置下的标签页共享登录 Cookie，不能作为独立身份。

1. A 创建小组，成为组长；B 使用 A 提供的 12 位邀请码加入小组。
2. A 在待认领任务列表中为该小组认领练习影像。B 作为成员不能代替组长认领。
3. 两台电脑进入同一任务的协同标注，确认都已取得最新共享成果。
4. A 在一处绘制，B 应看到对应更新；B 在另一处绘制，A 应看到增量。
5. B 使用不同标签编辑 A 已标注的同一区域，检查并列意见与作者提示；B 擦除自己的意见时，A 的意见应保留。
6. 暂时断开 B 网络并画一笔，再恢复连接，检查待确认操作恢复同步。也可在同一账户的“本地工作缓存”恢复工作，最终提交仍受当前任务权限检查。
7. 返回工作台再打开任务，或退出登录后重新登录，检查最新成果与本地缓存。关闭网页不保证上传继续执行，应先处理待确认操作。
8. 用派活账户只读监看更新，确认其无法修改；使用未入组的干活账户确认无法读取该已领取任务的影像或工程。
9. 最后由 A 以最新修订号确认完工，检查两台电脑现有连接都转为只读，再下载成果 ZIP。

成果 ZIP 应包含分割 NIfTI、标签说明与清单；有并列意见时另含 `parallel-annotations.json`。原始 CT/MRI 不随成果包导出。角色与权限细节见 [双角色控制台说明](role-console.md)。

## 5. 连接或同步失败时

- 在服务器先检查 `http://127.0.0.1:8787/api/health`，确认启动的是当前 Java JAR，且数据库与影像目录配置正确。
- HTTPS 访问检查证书名称、信任链和代理监听；SSH 访问检查隧道仍在运行、本机端口没有冲突，且没有更换浏览器访问网址。
- 浏览器网络面板应能看到同源 API 和 WebSocket。网页能打开但实时更新失败时，检查代理的 Upgrade/Connection 转发与长连接超时。
- 直接跨电脑访问 HTTPS 时，检查服务器防火墙和网络客户端隔离。若 HTTPS 代理运行在 Windows，可按实际端口添加仅限本地子网的规则，无需关闭防火墙：

```powershell
New-NetFirewallRule -DisplayName 'DeepMark LAN HTTPS 8443' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443 -RemoteAddress LocalSubnet
```

- 权限错误应检查角色、组员关系、认领小组和任务是否完工，不应通过换昵称或直接调用旧接口绕过。

这些步骤用于人工验证，不代表已经完成两台实体电脑、真实影像或公网性能测试。隔离的 HTTP/WebSocket 自动化测试入口见 [集成测试配置](role-console.md#http-与-websocket-集成测试)。
