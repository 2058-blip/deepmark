# 切片导航与网格性能修复

## 原因与修复

他人标注网格原本每帧按视口采样重新计算斜叉透明度，并为每个采样做坐标数组复制、映射及 Vue props 读取。一个方向翻片还会使三张网格都安排重绘。普通翻片不生成标注修订，现有缓存也会重用未变的大数组，因此本轮没有修改原生分割或存储内核。

- 普通切面与 MPR 的网格映射预先捕获几何系数、尺寸和步长，以标量查询替代热循环中的响应式读取与坐标数组分配；保持现有最近邻、剪切、反射、半体素边界与取整规则。
- 同一视口尺寸的斜叉采样位置与透明度只计算一次。切片、缩放和平移使用现有缓存；逻辑尺寸或栅格尺寸改变时重建，关闭网格或离开视图时释放。缓存仅覆盖视口，不复制整套 CT 或 Mask。
- 普通切面只因自身的 `point[axis]` 改变而重画网格；其他坐标引起的十字线更新仍由原生视口正常绘制。归属、掩膜、可见性、视图几何和 MPR 变化仍会刷新网格。
- 适配/全屏按钮改为深蓝灰背景 `#1b2c3d`、浅色图标 `#dcebf2`。提高选择器优先级，避免被通用浅色按钮规则覆盖；按钮功能不变。

## 性能证据

以下是同机 Node CPU 对照，使用 512×512×630 几何、约 22 万体素的稀疏合成贡献及 Vue shallowReactive 输入，不是浏览器端到端帧率。

| 网格层场景 | 原中位数 | 新中位数 | 原 P95 | 新 P95 |
| --- | ---: | ---: | ---: | ---: |
| 360×200 轴位 | 3.30 ms | 0.61 ms | 3.39 ms | 0.67 ms |
| 700×480 轴位 | 16.92 ms | 3.43 ms | 17.65 ms | 3.59 ms |
| 1400×850 轴位 | 60.09 ms | 12.26 ms | 63.71 ms | 12.87 ms |
| 1400×850 MPR | 67.47 ms | 17.01 ms | 68.22 ms | 17.36 ms |

4 组旧画法完整 RGBA golden，以及 60 组普通/MPR、不同缩放和响应式输入对照的像素哈希均一致。1400×850 的斜叉缓存约 3.31 MB；没有新增体数据副本。

## 验证边界

- 130 项 Node 测试、Vue 类型检查、生产构建通过。83 个原生文件及 12 个工具交互函数的基线保持。
- 在真实 `volume_bone.nii.gz`（512×512×630）中，单次轴位翻片前的网格重画次数为轴位/冠状/矢状 `26/25/25`，之后为 `27/25/25`；已恢复原切片。最近普通视图网格绘制约 1–2.4 ms，这是单层绘图耗时，不等于整个页面的帧时间。
- 浏览器已确认两个按钮实际为深色背景及浅色图标。测试未执行绘制、擦除或改变标注权限。
- 性能数据、截图、合成基准及浏览器记录在被 Git 忽略的 `artifacts/slice-performance/`。缓存初次构造、影像解码、原生重采样、网络或其他同时发生的操作仍会影响总体体验，未以这些数据宣称任意影像都能固定帧率运行。
