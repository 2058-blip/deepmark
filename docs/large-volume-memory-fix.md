# 大影像导入与动态区域生长内存修复

本次修改仅作用于 `deepmark-front-ui-polish`。用户确认的整合 UI 开发入口是 `http://127.0.0.1:5173/`，对应后端端口 8811。嵌入目录的独立内核入口不是该 UI 的验收入口。

## 原文件与改动

只读验证文件：`影鉴测试/volume_bone.nii.gz`，512×512×630，165150720 体素。Float32 CT 占 630 MiB，单个二值 Mask 占 157.5 MiB。保留完整尺寸、灰度、空间间距和方向；没有静默降采样。

- 大文件 SHA-256 改用增量流，避免 localhost 下另读整文件缓冲；取消会释放读取器。
- 下载每 8 MiB 封装 Blob 分段，最后仅组合 Blob 引用，减少结束时的整文件重复字节复制。
- 动态增长使用域内一位访问表及可回收 Uint32 分块 FIFO，保留原 FIFO 顺序、连通规则、严格灰度条件和在线均值。
- 自动补洞改为有界背景洪泛，去掉整卷行／连通段对象图；二值复制不用会物化数字列表的 TypedArray.from 映射。
- 动态增长与阈值任务不向 Worker 发送未使用的输入 Mask；较大 CT 的后台副本在任务结果或错误后销毁。
- 用计算结果新增 Mask 时直接采用已验证的结果数组，不再先分配同尺寸空 Mask。

动态增长和补洞默认辅助预算 64 MiB（访问表加队列，不含必需的完整分辨率输出）。超过预算明确报错，源不变，可以缩小 ROI 后重试。该限制是辅助计算工作集预算，不是恢复旧的固定体素配额。

## 验证与证据

- 平台测试 103/103，通过。
- 原生工作台测试 845/845，通过。
- Vue/TypeScript 和 Vite 构建通过；内核校验通过。
- `artifacts/oom-fix/bone-stress.json`：真实 bone 流式导入、真实 OperationClient + operations.worker 三维增长和 ROI 补洞通过。测试进程使用 128 MiB JS 堆，Float32/Mask 存于外部数组内存；峰值 RSS 约 1952 MiB。
- 受控骨内种子 [291,252,314]、偏差80/80、6邻接，增长583个体素；这是指定参数结果，不代表整块骨组织标注验收。
- `artifacts/oom-fix/bone-air-stress.json`：真实 bone 的外部空气种子 [0,0,0]，全三维、偏差80/80、固定均值、6邻接，选中112519713体素。动态计算8.366秒，峰值RSS约1853 MiB，Worker JS堆约12.12 MiB；在128 MiB JS堆限制下未出现OOM。
- 压测不替代浏览器验收。浏览器步骤应在用户确认的 5173 新 UI 中进行；不要用独立内核旧布局替代整合 UI。
