# 标注工作台：账户与协同接入

本分支以 `f2642ba` 的已优化编辑器为内核，接入主分支 `519bf4b` 的 Java 账户、小组、任务和数据集体系。根目录的网页入口为 `WorkbenchApp.vue`，独立离线版本仍在 `mimics-workbench/`。

## 使用流程

1. 派活账号上传 `.nii` 或 `.nii.gz`。
2. 干活账号创建小组，其他作者通过邀请码加入；组长为本组认领任务。
3. 成员点击“进入协同标注”，工作台加载服务器完整成果。顶部显示小组、作者、在线成员、连接状态、待同步数量和服务器修订。
4. 一笔画笔或一次工具操作完成后，客户端上传结果差量；服务器持久保存并通知同一任务的成员，各客户端获取差量并渲染。鼠标轨迹和窗宽窗位等本地显示状态不上传。
5. “操作记录”可打开固定修订的只读成果；“返回实时成果”重新加载当前成果。
6. 组长完工后全组变为只读。派活账号可只读监看；完工后可从任务列表下载原生 `.deepmark.zip`，包含 CT、独立 Mask、模型、测量及工程元数据。

鼠标在 CT 切片或 MPR 中的涂色区域静止满 0.5 秒后，显示该位置每个可见 Mask 的名称、颜色和全部标注作者，不再显示“标注信息”标题。同一个 Mask 的同一体素由多位作者共同标注时，作者并列显示；作者离线后仍能显示。未覆盖的位置、隐藏或透明度为零的 Mask 不显示提示。提示按源体素归属读取，不会把整个 Mask 的创建者冒充为每处区域的作者；未记录作者的本地导入成果显示“未记录”。

悬停读取已同步的稀疏作者位集合，不发送鼠标轨迹，也不按鼠标移动请求服务器。MPR 查询与绘制像素的最近邻 Mask 采样一致，保留倾斜、反射、剪切和半体素边界规则。鼠标移动立即隐藏并重新等待完整的 0.5 秒；开始拖动、离开视图或窗口失焦时取消提示。切片、缩放、影像和视图变化隐藏旧提示并重新计时，到期后才查询当前位置。

## 数据与权限

- 每个数据集/影像指纹有一个共享工程。采用原生独立二值 Mask，可以保留同一区域在不同 Mask 上的并列意见；使用多个完整工程版本分叉的旧逻辑不适用于此工作台。
- 服务端按 Mask 保存各作者的成员位集合，并取并集作为成果。擦除只撤回自己的贡献；删除包含其他作者贡献的 Mask 会受保护。非 Mask 对象被其他作者修改时产生并列对象，后续离线操作通过别名映射继续引用该对象。
- 账户、小组成员资格、发布者归属、任务状态、CSRF 和会话有效性由原有 Java 平台检查。请求中的作者绑定须与实际登录 Cookie 一致，不能仅凭浏览器传入的姓名认定身份。
- SQLite 存储共享成果、作者归属、操作日志、初始快照和模型资源；不创建每个作者的独立服务端工程空间。模型等二进制资源按 SHA-256 去重，Mask 差量为有序 DBW1 区间包。
- 浏览器保留用于显示的完整工程和按账号隔离的 IndexedDB 恢复副本；已完成操作立即进入上传流程，短暂失败时保留结果差量并重试。成功确认后移除待确认操作。退出前等待同步并刷新本地副本；同步失败时显示原因，不宣称已经保存到服务器。
- 网络消息可在绘制期间接收，投影到编辑器的更新会等当前手势完成，避免覆盖草稿。异步投影检查编辑器和服务器修订，防止旧请求覆盖新成果。
- 未声明单位的 CT 由作者确认，选择同步给团队；确认后不能在同一工程重新解释单位。Reslice Project 或打开另一份影像会进入本地派生工程，原共享工程仍保存在服务器。

## 既有成果迁移

首次进入新的工作台时，将同一 Java 平台数据库中的旧协同标签转换为 `legacy-<label>` 的独立 Mask，保留正向并列意见和同标签的多作者归属。迁移原始表、负向意见和日志继续保留，可从迁移前历史只读查看。旧编辑器对已迁移任务停止写入，防止产生两份互不相通的实时成果。独立 Node 版本的昵称数据库与 Java 账户数据库不同，不会自动关联。

原生历史从迁移初始快照开始重放，当前工作修订与 Mask 内部数据修订分别保存，撤销恢复 Mask 不丢失来源修订。历史回看不能向实时缓存写入。

## 本地启动

需要 Node.js 24+、JDK 17+ 和 Maven 3.9+。在仓库根目录执行：

```powershell
npm ci
npm run build
mvn -f backend/pom.xml package
$env:HOST='0.0.0.0'
$env:PORT='8080'
$env:DEEPMARK_ALLOW_HTTP='1'
$env:COOKIE_SECURE='0'
npm start
```

访问 `http://localhost:8080/`；同一局域网设备使用服务电脑的 IPv4 地址。默认账户数据库为 `server-data/platform/deepmark.sqlite`，CT 为 `server-data/datasets/`，网页为 `dist/`。可用 `STATE_DIR`、`DATASET_DIR`、`DIST_DIR` 指定既有 Java 平台的数据目录。测试注册账号会保存在所指定的数据库中，因此浏览器自动测试应使用独立测试数据目录。

上传大小仍由原平台限制为 512 MiB 压缩/原文件；服务器以流方式验证 NIfTI，已移除原标签图编码导致的 1.28 亿体素检查。浏览器导入保持完整分辨率，实际可用大小取决于浏览器地址空间和内存。旧标签图 API 的编码上限保留，不用于原生 Mask 协同。

## 验证与内核保护

```powershell
node scripts/verify-workbench-kernels.mjs
npm test
npm --prefix mimics-workbench test
mvn -f backend/pom.xml test
npm run build
```

保护检查对照 `workbench-kernels.lock.json` 的 83 个文件与 12 个既有工具操作函数。协同整合不能更新这份锁文件。新增代码主要位于 `src/workbench/` 和 Java 的 `WorkbenchCollaboration` / `WorkbenchModel`；`Workbench.vue` 仅增加控制器注入、协同栏、只读和导出权限等界面边界。Image/MPR 视口的确切插槽桥只传出悬停几何、当前倍率与既有滚轮处理；检查时仅剥离明确列出的桥接行，原生算法和交互函数保持原始字节。

悬停功能在 ImageViewport / MprViewport 各增加一条只读模板插槽，用于取得当前视图精确的位置映射。检查程序仅排除这两条完整且固定的插槽行，再与原始字节核对；锁文件、分割计算、画笔逻辑及原有交互函数保持原样。

真实 Edge 三账号验收：启动独立测试 Java 服务后，安装 Playwright 或设置 `PLAYWRIGHT_MODULE`，运行 `node --experimental-strip-types tests/workbench-browser.mjs`；`WORKBENCH_TEST_URL` 默认为 `http://127.0.0.1:8787`。测试通过网页注册角色、上传 CT、建组入组、认领任务、画笔同步、归属保护、独立 Mask、上传失败重载、确认响应丢失、历史回看、注释、3D 模型和完工 ZIP 下载。结果写入忽略的 `artifacts/`。

`WORKBENCH_PERF=1` 和 `WORKBENCH_TEST_NIFTI=<大体积文件路径>` 可执行双账号 60 帧绘制、擦除、局部阈值性能复测，报告为 `artifacts/workbench-integrated-performance.json`。离线优化的基准方法见 `mimics-workbench/docs/interaction-performance.md`。
