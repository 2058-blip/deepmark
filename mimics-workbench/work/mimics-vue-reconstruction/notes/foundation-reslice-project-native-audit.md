## Object retention is not specified by the local help

The Reslice Project reference and screenshot do not mention Mask, STL/Part, measurements, centerlines, Polylines, RP objects, selections, history or source-provenance transfer. Searches in the local help found transformation-file interoperability, but no explicit per-object retention/drop contract. Neither “native copies all objects” nor “native discards all objects” is justified. Copying or excluding any of these in the new application must be documented as its independent project-conversion policy.

## Coordinate contract for an independent conversion

Let `Aold` map source IJK centers to old world mm. Let `B=[u v n]` be the chosen orthonormal output-frame direction matrix, `O` the chosen first output sample-center world position, and `D=diag(pixelSize,pixelSize,sliceDistance)`.

- With Update CS **off**, preserve old world coordinates: output affine is `Aout=[B D | O]`. Each output voxel samples the source at `Aold^-1 Aout q`. Existing physical objects can retain their world coordinates, even where they lie outside the new image FOV.
- With Update CS **on**, choose and state a rigid old-world to new-world transform. For a sample-center-origin convention, `T(w)=B^T(w-O)`, giving `Anew=[D | 0]` and physical geometry transformed through the same `T`. If a support-corner-origin convention is chosen instead, its half-pixel offsets must be included consistently in affine, geometry and exported transform. The local native text does not resolve that choice.
- Distinguish the sampling map `M=Aold^-1 Aout` (new IJK → old IJK) from the coordinate-system change `T` (old world mm → new world mm). Their inverses have different meanings. Exported TXT should explicitly label units, direction, homogeneous matrix layout and the independently chosen convention; it must be usable for imported geometry.
- Rotation about the drawn line is a frame-selection operation. It must not accidentally rotate copied anatomy once for resampling and a second time when Update CS is off. Update CS re-expresses the same physical anatomy consistently with the new image frame.

The exact output extent, slice-count rounding, pixel support and interpolation are application policy until separately recovered. Nearest-neighbor Mask resampling must preserve each independent overlapping Mask; gray interpolation must not fabricate label mixtures. Out-of-source gray fill must be finite and explicit because the current file/project validators reject NaN/Infinity image data.

### Sheared source-slice and density ROI limitation

The existing `sourceSliceMprPlane` computes the source slice's physical normal and then calls `fitMprPlane`, which creates an orthogonal frame. That is suitable for a display plane, but it does **not** preserve a sheared source pixel lattice exactly. A two-corner density rectangle/ellipse defined in old IJK can represent a parallelogram/sheared ellipse in world space. Merely converting its plane through that helper and retaining two world corners changes its physical region silently.

For ordinary point-based planar measurements, an orthogonal frame on the same physical plane may retain their exact world geometry. For old IJK density ROI with in-plane shear, either add a representation that retains its full old basis/shape, or explicitly block/omit the unsupported conversion with an object-specific warning. Do not call a display re-fit a lossless conversion. New-grid density values may change because the underlying gray volume is resampled; retaining historical geometry does not preserve the old sampled numeric result.

## Priority Worker/controller counterexamples for the next phase

1. Same physical sample positions under Update CS off/on must yield identical gray/Mask arrays while copied geometry and exported matrix agree with their chosen world coordinate system. Use an analytic world-linear gray field and independent nearest-label oracle on a translated/reflected/sheared source.
2. Mask resampling retains overlap and source isolation; old/new data, headers, Parts and measurement arrays are detached. Historical provenance must not become falsely current.
3. Include IJK distance/area/annotation and density ROI, independent MPR measurement, label offset, Part normals/attachments, centerline topology/radii, RP/view plane, and Polyline. Every retained item must validate after conversion and ZIP roundtrip; every unsupported item must have an explicit omission/block reason.
4. Sampling boundaries, output finite fill, width-mm versus sample-count derivation, line reversal, presets, rotation sign, degenerate/near-collinear line, resource limits and cancellation must obey the documented independent policy.
5. A stale/failed/cancelled export or project installation must leave the entire original document, dirty/history/redo state and pending replacement identity intact. New project/transform output must be concrete before any user approval; browser inability to write beside an original imported file must be disclosed rather than claimed as native folder behavior.

## Implemented independent project-data conversion

After the evidence review, the coordinator explicitly assigned this agent `src/mimics/resliceProjectData.ts`, `tests/mimics-reslice-project-data.test.ts` and the necessary `project.ts` / `dicom.ts` coordinate-metadata schema changes. This implementation phase does not change the native evidence boundary above or any completion/acceptance gate.

The frozen exports are:

- `validateResliceProjectObjects(sourceVolume,sourceState,copyWorldObjects):void`.
- `buildReslicedProject(sourceVolume,sourceState,sampling,{name,copyWorldObjects,updateCoordinateSystem?})`, returning `{volume,state,transformationText,warnings}`. `sampling` is the geometry owner's `ResliceProjectGeometryResult`; the coordinator always supplies the frozen Update CS flag. When omitted, the metadata fallback detects a nonidentity coordinate transform.

The module leaves both source project and sampler buffers unchanged and detached from the result. It generates a new little-endian Float32 NIfTI-1 header with dimensions, mm units, sform, identity gray scaling and finite min/max. A single-voxel probe reuses `parseNifti`'s canonical float-header affine/spacing/oblique rules without allocating a complete throwaway image. Every independent Mask is matched by ID, copied separately and advances its revision once while keeping threshold/color/visibility/opacity. Historical Part and Centerline source revisions are preserved so they become stale rather than falsely current. The live object preflight inspects only spatial/object/version metadata, using a Mask version map; it never scans source image or Mask cells. Full `validateProject` runs at the actual build entrance and on the completed output.

World-object copy retains detached Part mesh positions/indices/normals, measurement points/control points/offsets/styles/Part attachments, world Centerline graph topology/radii and RP geometry. Old IJK measurement `plane` is removed and converted to a physical `mprPlane`; two-corner density geometry on a sheared native slice is rejected during preflight. Any native Polyline object also blocks world-object copy explicitly because its old-grid layer/ring schema cannot express the arbitrary transformed plane. Choosing image-and-all-Masks mode explicitly omits the physical groups, lists their counts in warnings, clears selected references, and keeps historical Mask source-Part orphan IDs under the existing valid orphan policy.

The old persisted IJK point maps through old world, `T`, then the new affine inverse with nearest/clamp; the transient tool becomes navigation and source axis becomes the new stack axis. Retained MPR view origin/step/crosshair and disabled state remain independent of selected RP geometry. Physical geometry is retained outside the new image FOV as historical geometry, rather than silently cropped or regenerated.

`DicomVolume.dicom.coordinateSystem` now accepts exactly `RAS` or `reslice-local`. Original DICOM import remains RAS. Update CS on marks the new output `reslice-local`, including an identity numeric transform; CS off preserves the source frame marker, so repeated reslicing never relabels an existing local frame as RAS. Modality, HU/GV, MONOCHROME1 display inversion and window metadata remain independent of gray values.

The explicitly added optional `ProjectState.resliceTransform` is nonempty UTF-8 text at most 65,536 bytes. Standard `encodeProject` writes an additional fixed `reslice-transform.txt` entry only when this exact field is present. Restore compares its bytes to the declared metadata and includes only that fixed path in referenced entries. Missing/mismatched text, an undeclared extra text entry and arbitrary unknown paths still reject. Legacy v1 files without the optional field remain unchanged. Repeated Reslice Project replaces the old transform with the new transform; history snapshots retain the immutable text string.

The text labels `T` old-world-mm → new-world-mm, inverse `T`, and new-IJK-sample-center → old-IJK-sample-center `Aold^-1 * inverse(T) * Anew`. It records Update CS and calls output `[0,0,0]` the **first stored sample center**, explicitly an application convention with native upper-left mapping unverified. It excludes vendor-format compatibility or automatic saving beside the original file. The standard project ZIP now carries a real transform TXT without an outer wrapper or broadening the unknown-entry whitelist.

## Data and schema verification

`tests/mimics-reslice-project-data.test.ts`: **14/14 pass**. Cases cover metre/mm/micron source units and both source byte orders; original scaled gray values and canonical new headers; ID-reordered overlapping Masks and stale provenance; CS off physical retention; CS on point/vector distinction across every supported object type; nested/buffer isolation from both source and sampling inputs; explicit image-only omission counts and source-orphan preservation; Polyline/sheared-density preflight; valid ordinary measurements on sheared source slices; matrix direction and sampling-map consistency; DICOM HU/display/frame behavior including identity CS update; rejected frame enums on save/restore; exact text-entry ZIP/history/legacy/corruption behavior; atomic rejection of malformed sampler results/options; and unreadable-cell Proxy guards proving that live preflight performs no image/Mask scan while actual build still rejects nonfinite source values.

An additional review hypothesis suggested a future derived `sourceRevision` could collide with the new Mask revision. Source inspection ruled it out: the existing full project validator already rejects a live Part/Centerline/Polyline revision greater than its referenced Mask revision. The original `revision+1` policy is therefore retained; the lightweight preflight checks the same object-reference upper bound without visiting voxel buffers. No unsupported future-revision fixture is described as a valid accepted source, and no broader provenance schema change was made.

The existing Project, DICOM and RP suites plus the new data suite pass **54/54**, no skipped/cancelled tests. Independent `npx vue-tsc --noEmit` passes. Root coordinates actual-controller/Worker integration and full regression/build. No native program or browser was run for this module, and native object-retention parity remains unknown.
