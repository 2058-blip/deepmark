# MPR Lasso / LiveWire: native boundary and integration audit

Scope: local extracted help text/CHM HTML and existing source/tests only. No original program, license, browser, network or patient data was used. This note records requirements evidence and implementation risks; it does not broaden the native-support claim or change requirement/acceptance gates.

The local help does not explicitly permit or forbid arbitrary Online RP source-Mask Lasso/LiveWire editing. No exact native MPR contour resampling/writeback algorithm was found. Implementing it is an independent application extension; statements about source-cell slab, sampling resolution, snapping and resource budgets must retain that label. The separate 3D LiveWire documentation and MPR Area measurement documentation are not substitutes for missing 2D Edit Masks evidence.

## Existing code and integration boundary

`useWorkbench.imagePick` currently captures an IJK `SlicePlane` contour transaction with source Volume identity, selected Mask ID, project revision, operation, local range and temporary-selection mode. `finishDrawing` validates that transaction, closes the LiveWire path to its first point, fills a single IJK polygon and either commits one direct Mask edit or changes only Multiple Slice Edit's temporary selection. `polygonRaster` is explicitly an independent even-odd fill at source integer centers with boundary included. It does not share Area measurement's simple-polygon rejection contract.

Existing controller tests cover direct IJK Lasso/LiveWire Add/Remove/Threshold, one Undo/Redo transaction, raw/other-Mask isolation, no measurement creation, preservation of temporary selection, target/operation/range/slice cancellation, pending-worker cancellation and degenerate/no-op contours. Those tests are useful regressions; they are not arbitrary MPR writeback evidence.

The current IJK LiveWire route asks `OperationClient` for a real worker `LiveWireTree` on an immutable source slice and uses `liveWirePath` for anchor and closing segments. The tree uses source integer IJK coordinates and physical spacing along its two axes. Its source comments distinguish recovered cost/normalization pieces from independent preprocessing and unconfirmed heap tie order. An MPR tree must instead identify its output sampling grid, allowed support and pixel-to-world mapping explicitly; reusing the algorithm does not recover a native arbitrary-MPR kernel.

`liveWirePath` returns an empty array for an unreachable target. Existing IJK anchor and closing code concatenates `.slice(1)` without explicitly rejecting an empty path. This is a review risk rather than a newly executed IJK regression: in an MPR sampling support map with holes/disconnected components, accepting that result could silently fall back to an implicit straight polygon edge. New MPR code should reject or clearly retain the provisional contour on an unreachable anchor/closing path, rather than commit an unsupported bridge.

At the pre-extension UI seam, `Workbench.chooseTool` closes MPR when choosing Lasso/LiveWire; `MprViewport.down` does not issue segmentation contour events for those tools. MPR `complete`/`cancel` still dispatch to global `finishDrawing`/`cancel`, and its generic world draft display is currently fed by measurement draft state. Enabling the tool allowlist therefore needs new qualified contour routes and separate session draft state, not just new buttons or a reinterpretation of measurement/IJK points.

## Priority independent counterexamples

1. **Session and anchor ABA:** Cancel and restart on the identical plane/Volume/project revision/pose/Mask. Old Begin/Point/Complete/Cancel and delayed path results must neither commit nor clear the new contour. A monotonic session ID/high-water and per-anchor/generation sequencing should be frozen before worker requests. Old promise cleanup must not clear the new session's busy/progress/draft state.
2. **Path validity and closure:** Reject unsupported seeds, off-plane points, wrong current planes, disconnected/unreachable target paths, and unreachable closing segments. Complete must use the actual closing LiveWire path, not an implicit straight chord after an empty result. A degenerate contour or a failed path cannot create history.
3. **Direct source-grid operations:** Use a hand-derived slanted-plane source-index set for Add/Remove/Threshold, with physical contour coordinates and full affine source cells. Preserve raw intensities/header/affine, other Masks, historical Parts/measurements/RPs, source-IJK point and white crosshair; preserve Multiple Slice temporary selection. Threshold source-value evaluation and immutable Mask default threshold follow the chosen independent writeback policy.
4. **Frozen ownership/configuration:** Require complete active Mask/source-buffer, Volume, document revision, pose, physical plane and session identity at every input/complete event. Current-session malformed input cancels or rejects according to one documented policy; foreign session events ignore without clearing the new draft. Operation, selected threshold, visibility, tool, plane/pose, source install and LiveWire parameter changes invalidate unfinished work, including away-and-back cycles.
5. **No global fallback:** MPR Enter/double-click/Lasso release and toolbar completion must close only the correct MPR contour. They must not complete an old source-IJK contour or measurement, reset a newer MPR session, or create a measurement object. Qualified Cancel must not call a no-argument global cancel on a late viewport event.
6. **History and resource failure:** Completed contours create one transaction; placing anchors/paths remains provisional. Cancel, allocation/worker errors, too many points or raster/path budget exhaustion leave source membership and genuine undo/redo branches unchanged. If anchor undo is offered, define it as transient editing independently of global document Undo and test pending result invalidation; do not call it recovered native behavior.

## Agreed application contract and independent workflow suite

The controller contract adds `e.mpr.beginContour`, asynchronous `contourPoint`, tree-only `previewContourPoint`, asynchronous `completeContour`, qualified `cancelContourGesture` and explicit manual `cancelContour`. The required `MprContourEpoch` freezes positive safe-integer session ID, active Mask ID, physical plane, Volume identity, project revision and MPR pose revision. Accepted-session high-water identity prevents old Begin replay. All malformed/foreign Point/Complete/Cancel events must ignore without clearing the current draft. Session state separately exposes world points, committed anchors, hover path and pending state. Completed edits alone publish a source Mask/history transaction.

The owned `tests/mimics-mpr-contour-workflow.test.ts` contains eleven independent cases, initially written before the production API landed. Lasso passes its local world polygon at Complete; `contourPoint` is deliberately the LiveWire-only anchor route:

1. Hand-derived oblique source-cell Lasso Add/Remove/Threshold. For the identity source grid and `z=x/2+0.13`, the slab simplifies to `2z-x` in `{-1,0,1}`. A containing physical polygon edits exactly those expected source centers. The unfinished session stays private, each accepted close creates one project/Mask revision, Undo/Redo is exact, and real-worker ZIP retains source and other Masks.
2. Uniform-source axial MPR LiveWire uses adjacent boundary anchors around a 3-by-3 rectangle. Each minimal accepted path is an adjacent edge, allowing expected source membership without deriving it from the production helper. Add/Remove/Threshold each close the actual final path in one reversible transaction.
3. Every mandatory epoch field, malformed and foreign identity, wrong plane/Mask/source/revision/pose rejects across Point/Hover/Complete/Cancel. Invalid Begin cannot clear the current draft. Draft identity and contents remain unchanged through ignored events.
4. Cancel and restart at identical document/pose geometry: old Begin/Point/Hover/Complete/Cancel cannot affect the replacement session, while its fresh completion succeeds.
5. Too few points, collinearity, NaN and off-plane geometry cannot write any source membership or consume history. A new valid session can complete afterward.
6. The worker adapter holds a real `mpr-contour-livewire` result. Cancel the old pending session, begin another and hold its genuine result too; releasing the old callback must not alter the new draft or clear its pending state. Releasing the current result completes its own anchor.
7. Hold an actual completed Lasso raster result, cancel that session, then hold a replacement raster result. Releasing the old result cannot commit source data, consume history or clear the replacement pending outline. Releasing the new result commits exactly once.
8. A fully finite thin source volume `[15,1,5]` and physical plane `origin=[10,-4,2]`, `u=[1,2,0]`, `v=[-2,1,0]`, `size=[3,5]` form disconnected supported output pixels `[0,4]`, `[1,2]`, `[2,0]`. Unsupported seeds and targets across these eight-neighbor islands must reject. The accepted anchor/path cannot gain an implicit straight bridge, and closing an incomplete contour cannot edit source data. This does not bypass the NIfTI finite-value validation.
9. Pose, active Mask, operation, effective selected threshold range, visibility, tool and LiveWire parameter changes invalidate unfinished sessions, including away-and-back cycles. The only document transactions in the visibility check are the explicit visibility edits.
10. Global threshold controls and inactive local/LiveWire settings do not cancel Lasso Add. LiveWire hover uses the resident tree without another worker request; clearing hover preserves provisional anchors, and one anchor cannot complete.
11. Intentional `ProjectHistory.push` failure leaves state identity, raw/other object data, clean state and a real redo branch unchanged. Retrying succeeds once; closing an already-applied no-op region creates no history.

The tests use actual workbench/Worker exchange, a synthetic NIfTI source, independent overlapping Mask, historical Part/measurement/RP objects, temporary selection, and separate white/source crosshairs. The held-result adapter delays delivery of actual computed tree/raster results rather than replacing the geometry/path algorithm.

## Verification and corrections

During the first run, three test-harness assumptions were corrected to the agreed application contract: Lasso has no controller anchor API; unsupported-data testing uses the finite thin-volume geometry rather than a NaN NIfTI rejected by the genuine parser; and a selected-range cycle uses genuinely different effective bounds instead of selecting an identically valued preset. Production behavior was not weakened to accommodate those assumptions.

The initial run also exercised the legacy LiveWire-parameter watcher racing a newly begun valid MPR session. The controller owner independently identified and corrected that watcher to flush synchronously, preventing an earlier queued parameter notification from globally canceling the later session. The real-worker positive LiveWire and hover cases pass after that correction. No further concrete controller defects were found in the final independent read.

Final command: `node --experimental-strip-types --test tests/mimics-mpr-contour-workflow.test.ts`. Result: **11/11 pass**, no skipped/cancelled tests, approximately 1.67 seconds. Independent `npx vue-tsc --noEmit` passes. Root coordinates combined regression/build and reports. No shared source files, requirement inventory or acceptance gate are changed by this audit; native arbitrary-RP contour/writeback parity remains unknown.
