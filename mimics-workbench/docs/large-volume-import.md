# 大体积 CT 导入与本地恢复（2026-11-05）

本次修改用于独立 Mimics 离线工作台，保留此前的三维内存优化，没有更新协同服务器。

## 容量与读取

- 移除 NIfTI 解析、DICOM 系列转换、Mask 创建、工程恢复与物理轮廓源检查中
  写死的 134,217,728 体素限制。NIfTI-1 单轴维数和现有 Uint32 体素地址格式
  仍须有效，不承诺无限大小；实际还受浏览器数组分配能力和可用内存约束。
- NIfTI 先验证 352 字节头和空间信息，再将原文件或 gzip 解压流直接转换到
  最终 Float32 数组。除最终影像外，只保留小块输入和不足一个标量的尾字节，
  不再拼接整份解压文件。支持取消、进度、原有整数/浮点类型、大小端与灰度缩放。
- 导入与浏览不再立即启动计算 Worker，使用算法时才复制常驻计算影像。
- 工程验证与 ZIP 读写移除旧的 512 MiB 单项、1 GiB 总量预算，保留 ZIP32
  格式大小边界、调用者显式资源预算、元数据限制和内容完整性检查。
  小端平台恢复和编码数值数组时避免不必要的整卷复制。

## 本地缓存

大 Mask 不能直接作为一条 IndexedDB 记录保存：浏览器实测拒绝了
201,327,153 字节的记录，提示单条记录最大为 133,169,152 字节。

缓存数据库升级到版本 2，新增二进制块和引用清单，不删除既有版本 1 数据。
大影像、Mask 和模型数组按 16 MiB 分块；短数组只复制视图自身的字节范围。
先逐块提交，全部成功后再原子提交工程、源影像引用和列表摘要。发布失败时
中止事务，旧成果保持可恢复；成功后清理该工程不再引用的数据块。

现代 Edge/Chrome 使用 Web Locks 保护跨页读取、保存与回收。未变化的数组
复用已提交块，切换切片和显示设置不重写整份影像或 Mask。缺少 Web Locks
的旧环境优先保留数据、跳过块回收，可能多占磁盘。现有内存撤销预算不变。
此格式只用于浏览器缓存，不改变 NIfTI、STL 或 Deepmark 工程 ZIP 格式。

## 验证

- 单元/工作流测试 814 项，类型检查与生产构建通过。
- 分块解码覆盖全部 8 类支持的标量、两种字节序、缩放、非对齐输入、
  头/数据截断、非有限值、gzip 损坏与取消。容量规划验证超过旧上限的
  多种尺寸，无须为头测试分配虚假大数组。
- 512×512×768、0.60/0.60/0.70 mm 合成影像共有 201,326,592 体素，
  超过旧限制 50%。完整读取原始 .nii 和 .nii.gz 后，首值 -1234、尾值 2345、
  中心值 40 及总数量均正确；原始大小 402,653,536 字节。
- 实际 Edge 文件模式验证两种格式导入、四视图、本地保存；绘制 80 体素后
  刷新并恢复，仍为 80 体素。纯导入和手工绘制未启动计算 Worker，无页面异常
  或网络请求。该合成案例导入至缓存完成约 3.6–3.8 秒，不是任意真实 CT 的承诺。
- 真实 IndexedDB 验证版本 1 读取升级、未变化数据复用、视图更新零二进制重写、
  模拟发布失败后原成果完整、新工程失败不留下半份工程，以及旧块/孤立块回收。
  浏览器测试脚本为 tests/workspace-cache-browser.mjs，可传入 Playwright 模块路径。

压力测试合成数据、日志和截图位于 git 忽略的 artifacts/large-import-*，
不上传真实 CT、浏览器缓存或运行数据库。
