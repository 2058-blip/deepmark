# DeepMark 医学影像协同标注平台

DeepMark 提供数据发布人员与标注人员两套工作台，以及共享的三切面标注编辑器。前端使用 Vue 3、TypeScript、Canvas 和 Web Worker；Java 17+、Javalin 6、WebSocket 与 SQLite 提供生产账户、任务、影像和协同服务。

Node.js 24+ 用于前端构建、测试和开发编排。生产 API、WebSocket 和 `dist` 网页均由 Java 进程提供。当前编辑器没有使用 Cornerstone3D，也没有在浏览器或 Node.js 中运行 3D Slicer 的 Qt/VTK 代码。

本分支提供浅色标注工作台、切面最大化、自适应标签编辑与协作身份展示。界面操作和运行方式见 [工作台说明](docs/ui-integration.md)，双账号验收见 [多人协作测试步骤](docs/collaboration-manual-test.md)。在线成员与标签创建者由本分支的 Java 接口提供。

## 账户角色与任务流程

注册时选择角色，登录后进入对应工作台。权限由服务器账户与会话确定。

| 能力 | 数据发布人员 `dispatcher`（派活） | 标注人员 `worker`（干活） |
| --- | --- | --- |
| 上传、发布 NIfTI 影像 | 可以 | 不可以 |
| 查看发布记录、任务状态和小组进度 | 查看自己发布的任务 | 查看可认领任务与本组任务 |
| 创建小组、邀请码加入小组 | 不可以 | 可以，创建者成为组长 |
| 认领未标注任务 | 不可以 | 仅组长可以为自己的小组认领 |
| 修改共享标注 | 不可以，只读监看 | 领取小组成员可以 |
| 确认任务完工 | 不可以 | 仅领取小组的组长 |
| 下载已完成成果 | 可以 | 可以访问本组成果 |

任务依次经历 `unassigned（未领取） → in_progress（标注中） → completed（已完工）`。派活账户通过网页上传 `.nii` 或 `.nii.gz`；组长使用小组认领任务，成员通过 12 位邀请码入组后共同标注。并发认领由数据库事务裁决，一个任务只会分配给一个小组。

发布人员可以实时只读监看自己的任务。非领取小组成员无法读取该任务的影像或工程。组长确认完工时必须使用最新修订号；完工后 HTTP 与已经建立的 WebSocket 都会拒绝继续编辑。

完整权限、API 行为和集成测试配置见 [双角色控制台说明](docs/role-console.md)。

## 开发与构建

需要 **JDK 17+、Maven 3.9+、Node.js 24+**。最终使用者只需支持 Web Crypto、Canvas、Web Worker 与 IndexedDB 的新版 Edge 或 Chrome。

在仓库根目录执行：

```sh
npm ci
npm run build:server
npm run dev
```

`build:server` 使用 Maven 构建 `backend/target/deepmark-server.jar`。`npm run dev` 启动 Java 子进程与 Vite，并代理同源 `/api` 和 WebSocket；它要求 JAR 已存在。修改 Java 代码后需要重新打包并重启开发服务。

开发网页通常位于 `http://127.0.0.1:5173`，Java API 默认位于 `127.0.0.1:8787`。账号注册、登录与影像指纹验证使用 Web Crypto，远程浏览器访问需要 HTTPS；HTTP 仅用于本机回环地址开发测试。

可选生成合成练习影像：

```sh
npm run sample-data
```

命令在数据集目录生成 `合成练习影像.nii.gz`，不包含患者资料。使用派活账户在网页中选择该文件并上传发布；直接放入服务器目录不会自动创建当前平台的任务。

构建生产文件并直接启动 Java：

```sh
npm run build
npm run build:server
java -jar backend/target/deepmark-server.jar
```

`npm start` 是上述 Java 启动命令的便捷入口；生产机器直接运行 JAR 时不需要 Node.js。Java 服务默认提供 `dist` 中的网页及同源 API、WebSocket。

## 配置

[.env.example](.env.example) 是环境变量参考。当前 Java 与开发脚本不会自动读取 `.env`；请通过操作系统、进程管理器或终端导出变量。不要将实际密码、令牌、数据库或私钥提交到仓库。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Java 监听地址；开发脚本中也控制 Vite 地址，Java 子进程仍绑定回环 |
| `PORT` | `8787` | 直接启动 Java 时的端口 |
| `API_PORT` | `8787` | `npm run dev` 启动的 Java API 端口 |
| `JAVA` | `java` | 开发脚本调用的 Java 可执行文件 |
| `STATE_DIR` | `server-data/platform` | 当前平台数据库目录，文件名为 `deepmark.sqlite` |
| `DATASET_DIR` | `server-data/datasets` | 已上传原始影像存储目录 |
| `DIST_DIR` | `dist` | 构建后的前端目录 |
| `COOKIE_SECURE` | 未设置 | `1` 强制 Cookie 使用 Secure；HTTPS 请求自动使用 Secure |
| `DEEPMARK_CHALLENGE_TTL_SECONDS` | `120` | 登录挑战有效期，允许 1–300 秒；短有效期供隔离测试使用 |

配置示例（PowerShell）：

```powershell
$env:STATE_DIR = 'C:\DeepMarkData\platform'
$env:DATASET_DIR = 'C:\DeepMarkData\datasets'
java -jar backend/target/deepmark-server.jar
```

## 账户与传输安全

- 用户名为 3–40 位英文字母、数字、下划线、点或短横线，由服务器统一为小写。密码为 8–128 个字符，UTF-8 不超过 256 字节，不含控制字符。
- 网页先获取一次性挑战与 RSA 4096 位公钥，再用 RSA-OAEP SHA-256 加密挑战编号和密码。注册、登录接口拒绝明文 `password` 字段；挑战默认 120 秒过期，并在一次解密尝试后消费。进程重启会生成新密钥，浏览器需重新获取挑战。
- 数据库按账户保存独立的 24 字节随机盐，以及 PBKDF2-HMAC-SHA256、600,000 次迭代生成的密码验证值。密码验证使用恒定时间比较；不保存可还原的密码密文。
- 会话使用随机令牌，数据库只保存其 SHA-256 摘要。浏览器通过 HttpOnly、SameSite=Lax Cookie 持有会话；HTTPS 使用 Secure，默认会话有效期 30 天。
- 写请求需要 `X-Deepmark-Request: 1`，并进行同源校验。WebSocket 使用同一账户会话，服务端检查任务权限、成员关系和完工状态；不能依靠修改前端角色绕过权限。
- 同一浏览器重新登录会替换旧会话，其他设备的独立会话不受影响。注销会撤销当前会话；已建立连接后续仍会检查会话与任务权限。

RSA 密码载荷加密与 HTTPS 各有职责：HTTPS 还保护网页、公钥、Cookie 与影像标注内容。后端只信任本机代理传来的 HTTPS 协议头。当前不包含邮箱找回、MFA 或统一身份提供方接入。

## 影像查看与编辑器

- 支持三维灰度 NIfTI-1 单文件 `.nii` / `.nii.gz`，支持常见整数、浮点、大小端和灰度缩放。
- 轴对齐影像显示解剖切面与方位；斜切或缺少方向信息时显示原始 I/J/K 并提示，当前不会自动进行斜切重采样。
- 三切面联动、滚轮和滑条翻页、窗宽窗位、标签名称与颜色、隐藏与透明度调节。
- **B** 画笔、**E** 橡皮擦、**G** 灰度分区；**Ctrl+Z** 撤销，**Ctrl+Shift+Z / Ctrl+Y** 重做。
- 灰度阈值使用缩放后的原始灰度，包含上下限并作用于三维影像；预览不写入标签，应用后可撤销。
- 按灰度区间和 8 邻域连通性生成切片区域，或以悬停位置的灰度预览相连前景；点击后将当前切片的选区加入标签。孔洞和不相连区域分别处理。
- 区域计算在 Web Worker 中执行，仅保留最新悬停请求。交互参考 Slicer Level tracing，但没有逐行移植其 ITK 算法，不保证轮廓逐像素一致。
- 默认过滤原始灰度低于或等于 -900、且与切片边缘相连的外围空气，可调阈值或关闭；封闭内部气腔保留，已有标注不会因此被清除。
- **Ctrl + 按住鼠标右键上下拖动**缩放，范围 25%–800%，视图百分比按钮恢复 100%。缩放与窗宽窗位属于本机显示设置，不生成协同编辑。
- 悬停标注显示标签与作者，并列意见分别展示。来源未知或本机待确认时显示相应状态。

## 共享成果、并列意见与本地恢复

每个领取任务使用一份共享成果，小组成员在不同位置编辑会合并到同一工程。同一区域存在不同作者的意见时，仅为冲突区域保留并列标注及作者来源，不复制整份工程。擦除、阈值清除与撤回仅能删除当前作者自己的意见，其他作者内容由服务器保留。

画笔拖动期间在本机预览，松开后提交一次完成的体素增量。服务端持久化修订并通过 WebSocket 推送权威增量，HTTP 用于提交回退及补取缺失修订。同一操作编号重试不会重复执行。工程打开或恢复时读取完整成果，日常编辑使用增量同步。

IndexedDB 保存本浏览器的原始影像、工作副本、标签、继续位置及待确认操作。连续长笔画会记录中途检查点，视图设置使用轻量缓存。断网恢复时先取得最新共享状态，再由服务器重新检查待提交操作的账户与任务权限；本地缓存不会绕过完工锁定。

切换任务或退出登录前需要处理尚未确认的工作。关闭网页不能保证上传继续执行，清除站点数据会删除浏览器缓存；重新打开网站仍需要能取得网页资源，当前未实现完整离线安装。

成果 ZIP 包含 `segmentation.nii`、`labels.json`、`manifest.json` 和说明文件。有并列意见时另含 `parallel-annotations.json`，以完整保留各作者意见；单一整数标签图不能同时表达这些并列意见。原始 CT/MRI 不打入成果包，导出的 NIfTI 可在 3D Slicer 等工具中继续查看。

## 持久化与旧数据

SQLite WAL 保存当前账户、小组、任务、协同工程和修订；影像原文件保存在 `DATASET_DIR`。备份应同时保留数据库与影像，在线备份采用一致性备份方式，不应只复制正在写入的主 SQLite 文件。

当前平台默认数据库为 `server-data/platform/deepmark.sqlite`，与旧昵称团队版 `server-data/collaboration/` 数据分离。旧账户、团队、个人空间和标注成果**不会自动迁移**；请保留旧库与原始影像，迁移需要单独制定映射和校验方案。不要用新服务直接覆盖旧运行目录或数据库。

`server/` 保留旧协议测试 fixture，**不是生产启动入口**。历史测试或样例脚本可能复用其中的辅助代码；当前生产实现位于 `backend/`，不要执行旧 `server/server.mjs` 来代替 Java 服务。

## 生产部署

Linux 独立部署见 [部署说明](deploy/README.md)。脚本使用独立的 Java 后端和 nginx 配置，默认后端仅监听 `127.0.0.1:8787`，HTTPS 入口为 `8443`，支持同源 HTTP 与 WebSocket、512 MiB 上传和长连接。

部署运行数据默认位于 `/home/deepmark/runtime`，与源码目录分开。默认 SAN 证书为自签，包含 `ddns.984797.xyz`、`localhost` 和 `127.0.0.1`；浏览器正常信任需要安装有效证书或在测试环境明确信任该证书。端口监听不等于公网可达，仍需验证路由、防火墙和证书。

后台监督脚本可在 SSH 断开后保持运行，并重启异常退出的 Java 进程。当前服务器以 bash 为 PID 1，没有已接入的 systemd 或容器启动挂钩；**容器重启后仍需由宿主机或容器入口重新执行启动脚本**。部署脚本不会修改已有站点或停止不属于本应用的进程。

## 测试与当前边界

```sh
npm test
npm run build
mvn -f backend/pom.xml test package
```

`npm run test:platform` 面向正在运行的 Java 服务，需要显式指定隔离测试 URL 与位于系统临时目录的数据库路径，详见 [集成测试配置](docs/role-console.md#http-与-websocket-集成测试)。不要将该测试指向生产数据库。旧浏览器回归脚本中的旧协议 fixture 与当前 Java 平台不是同一入口，测试结果应按实际运行的版本和服务分别判断。

以上是执行入口和覆盖说明，不代表当前环境已经完成全部验证。真实医学影像、多台设备、公网延迟和并发容量需要分别测试。

当前限制：

- 输入不包含 DICOM、NIfTI-2、4D 或多通道；没有 AI 分割、种子生长、三维表面重建或直接运行 Slicer 的能力。
- 体素上限为 **128 × 1024 × 1024 = 134,217,728**。大文件解析、分割和缓存仍受浏览器内存与磁盘限制。
- 单次编辑的二进制增量上限为 **32 MiB**，Base64 与 JSON 传输会增加体积；WebSocket 消息上限另外限制。512 MiB 文件上传限额不代表可处理同等内存规模的任意影像。
- 灰度分区和外围空气过滤基于灰度及连通性，需要按影像调整参数；它们不提供器官识别。
