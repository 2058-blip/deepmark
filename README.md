# 医学影像标注工程师客户端

Vue 3 + TypeScript + Vite 前端，Canvas 切片显示，Web Worker 灰度分区，Node.js 24 + WebSocket + SQLite 共享标注服务。当前只提供标注工程师工作界面，不提供管理员端。

## 启动

开发和服务器需要 Node.js 24+，最终用户只需要新版 Edge / Chrome。

```powershell
npm ci
npm run sample-data
npm run dev
```

网页通常为 http://127.0.0.1:5173 ，API 默认在 8787 端口。`sample-data` 仅生成合成练习影像，不包含患者资料。

```powershell
npm test
npm run build
npm start
```

生产模式打开 http://127.0.0.1:8787 。Node.js 同时提供打包后的 `dist` 网页、数据集与协同 API。公开部署需要配置 HTTPS 和 WebSocket 转发；GitHub 仓库本身不会运行服务器。

配置：`DATASET_DIR` 指定服务器影像目录，`STATE_DIR` 指定持久数据库目录，`HOST` 默认 `127.0.0.1`，`PORT` 为生产端口，`API_PORT` 为开发 API 端口。HTTPS 可设置 `COOKIE_SECURE=1`。

两台电脑的局域网协同测试步骤见 [局域网测试说明](docs/lan-testing.md)。支持以局域网 HTTP 地址测试编辑、上传与断网续传。

## 影像查看与手动标注

- 三维灰度 NIfTI-1 `.nii` / `.nii.gz`，支持常见整数、浮点、大小端和灰度缩放。
- 轴对齐影像显示解剖切面和方位；斜切或缺少方向信息时按原始 I/J/K 显示并提示，不伪装为已重采样的标准切面。
- 三切面联动、滚轮或滑条切片、窗宽窗位、标签名称与颜色、显示隐藏和透明度。
- B 画笔、E 橡皮擦、V 定位、G 灰度分区。画笔覆盖当前区域，橡皮擦只擦除当前标签。
- Ctrl+Z 撤销，Ctrl+Shift+Z / Ctrl+Y 重做。单人模式支持原有分割导入与 ZIP 导出（内含 NIfTI 和标签说明）。
- 阈值工具使用原始缩放后灰度，包含上下限，对三维影像应用；预览不写入标签，应用后可撤销。

## 灰度分区与悬停轮廓

默认启用“悬停显示灰度区域轮廓”。鼠标在影像上移动时以黄色线显示所在灰度区域的边界，预览不会改变标注，也不会上传操作。

选择“灰度分区”后点击预览区域，将其加入当前标签，只作用于当前切片。整个选区作为一次编辑，支持撤销、重做和协同上传。

两种方式：

1. **灰度区间分区**：按可调区间宽度划分原始灰度，并用 8 邻域连通性形成区域。例如宽度 100 对应 0～100、100～200 等半开区间，负灰度同样处理；同灰度但不连通的部分分开。
2. **悬停灰度等值区域**：以鼠标处灰度为下限，预览相连的前景区域。它实现类似 Slicer Level tracing 的悬停、点击交互，但不是逐行移植 ITK 的链码算法，不能认为轮廓逐像素完全一致。

区域计算在 Web Worker 内执行，鼠标移动只处理最新请求，切片改变会丢弃旧结果。轮廓包含孔洞边界，点击不会误填其他灰度孔洞。灰度宽度不是器官识别或 AI 模型，请根据影像调整。过于复杂的轮廓会提示调整参数。

## 滚动性能

- 滚轮事件按动画帧合并，保留累计切片位置；只重算实际改变切片的视图。
- 复用显示画布、标签图层与像素缓冲；灰度缓存每个视图约 20 MB，窗口参数改变时重新生成。
- 改变另两个视图的十字线位置时复用已有灰度图；悬停轮廓独立显示，不反复重绘底图。
- 滚动暂停后再计算新切片的灰度区域，避免后台分区抢占快速翻页。
- 协同通过 WebSocket 直接接收标注结果增量；编辑过程中不反复下载或解压整份标注。位置参数只写入轻量本地元数据。

已用合成 512×512×24 体积验证滚轮合并、视图复用、悬停与区域填充；真实影像和不同硬件的性能仍需分别验证。

## 服务器数据集与单一共享成果

把影像放入 `server-data/datasets/` 或 `DATASET_DIR`，可以用子文件夹分类。网页“服务器数据集”支持列表、搜索、大小、更新时间、“下载并标注”和原文件下载。刷新列表会发现增删文件，无需重启服务。

当前服务器对应一个团队，作者只需登录一次。打开任意服务器数据集时自动获取团队最新完整标注及并列意见，再叠加本浏览器尚未确认的操作。切换数据集保留作者登录，不需要逐个加入协同。未登录或团队成果加载失败时，该服务器数据集暂不能编辑，防止误作本地标注。没有作者私有的服务器工作空间，也没有整份工程的分支版本。原始影像内容改变会创建另一共享工程，避免复用错误坐标网格。

标注人员权限相同，自行协调分工。不同位置的编辑合并到同一成果。两位作者在同一区域给出不同结果（包括先后操作）时，仅在该区域生成并列标注，保留作者和标签；后续在别处编辑不复制整份数据。点击并列条目可以定位并查看意见。

本地、共享成果及本地工作副本均导出为一个 ZIP，包含 `segmentation.nii`、`labels.json`、`manifest.json` 和使用说明。存在并列意见时，ZIP 额外包含 `parallel-annotations.json`，完整保留各作者的区域意见。解压后可将 NIfTI 导入 3D Slicer；原始 CT 不打入标注包。操作历史保留修订记录，只读查看历史不会创建新工作分支。

当前工程师端不提供最终审定界面。后端保留受权限控制的审定接口，工程师客户端不会调用它们。

## 本地缓存、上传与退出

画笔和橡皮擦拖动期间只在本机预览，不发送鼠标轨迹或途中笔画；松开鼠标后立即通过 WebSocket 发送本次完成标注改变的体素、前后标签、操作编号及修订号。区域填充、阈值、撤销、重做及标签设置同样在完成后发送，不上传完整工作副本。

服务器实时合并到完整共享标注，在 SQLite WAL 事务中持久化操作、权属与区域意见，提交后直接推送权威体素结果和并列意见。客户端在本地增量更新画面，包括自己正在画另一笔时收到的远端结果；未完成的本机笔画保留到松开后提交。服务器维护有界内存模型，持久日志与已有快照可在重启或模型淘汰后重建完整成果，不再为每笔编辑反复压缩整套体积。

正常联网时发送不等待 IndexedDB 写入或完整本地副本保存；本地缓存独立进行，用于断网恢复。WebSocket 不可用时可使用 HTTP 提交，连接恢复后按连续修订号补取遗漏的增量，重复编号重试不会重复执行。每 5 秒的检查仅用于补漏，不决定正常实时推送的等待时间；打开数据集、恢复旧数据或查看历史时才需要完整快照。

“本地工作缓存”保留原始影像、完整工作副本、标签、继续位置和待上传操作。已上传操作移出队列后，完整本地副本仍在。连续长笔画约每 700 ms 保留中途检查点；翻页、窗口和工具设置用独立元数据缓存，避免为翻页反复复制整个标注数组。

`tests/realtime-browser.mjs` 用合成 512×512×64 体积验证拖动不上传、松开后一次提交、慢缓存不阻塞同步、实时增量渲染、并发笔画保护及客户端与服务器结果一致性，并记录松开到另一端绘制的延迟。测试使用同机两个独立浏览器会话，不代表两台实体电脑或公网网络的实测延迟。

“退出团队”先完成本地缓存和剩余操作提交，再注销会话，不再归档作者服务器副本。网络失败时可继续工作或“保留本地缓存并退出”。关闭网页不能保证后台上传继续执行，之后从本地缓存恢复并续传；联网恢复时先取共享最新成果，断网回退会明确提示缓存模式。

当前使用可信团队的昵称会话和浏览器身份恢复凭据，尚无正式账号与跨设备身份恢复。清除全部站点数据会删除本地缓存和恢复凭据。网页资源本身尚未做完整离线安装，重新打开网站仍需网页资源可访问。

## 数据升级与边界

从旧版升级时先备份数据库到 `STATE_DIR/migrations/before-single-result.sqlite`，把旧工程分支差异转换为区域并列标注，再移除活动数据库的 `personal` 与 `branches` 表；旧个人空间 API 返回 410。原始影像、数据库、管理员预留密钥和备份均不提交到 GitHub。

当前不包含 DICOM、NIfTI-2、4D、多通道、AI 分割、种子生长或三维重建。体素上限 128×1024×1024；单笔上传编码上限 32 MB。大文件读取、分割应用与缓存仍受浏览器内存和磁盘容量影响，尚未进行大并发压测。当前没有使用 Cornerstone3D，也没有直接运行 Slicer Qt/VTK 代码。

团队登录与切换回归测试：`tests/dataset-switch-browser.mjs` 验证一次登录后跨数据集自动同步、切换不注销、不重复登录、B 打开后立即取得 A 已有成果、刷新保留身份，以及本地影像模式不影响团队登录。
